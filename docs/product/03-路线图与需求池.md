# 路线图与需求池

- 配套文档：[需求管理流程与 PM 把关规范](./01-需求管理流程与PM把关规范.md)、[产品需求文档 PRD](./02-产品需求文档PRD.md)
- 规划方法：采用 **Now / Next / Later** 滚动规划（不承诺具体日期，按价值与成本动态调整），候选需求在通过 PM 评审（DoR）前**不代表承诺**。
- 优先级：MoSCoW（M 必须 / S 应该 / C 可以 / W 本期不做）。

## 1. 当前阶段主题（Now）

当前产品核心闭环（扫描→浏览→播放→转码→续播→组织→分享）已完整，处于**能力巩固与体验打磨期**。本阶段优先：

1. 守住"零数据库默认、可选能力平滑降级、低配 NAS 友好"三条产品基线不被破坏。
2. 为已交付能力补齐需求卡与验收标准（历史功能反向归档，见第 4 节）。
3. 后续任何新需求一律先过 [PM 把关流程](./01-需求管理流程与PM把关规范.md)，再进入开发。

> 说明：Now 列表默认只收纳"已评审进入 Ready/In Dev"的需求。当前没有正在开发中的新需求，故 Now 以巩固项为主；新需求经评审后从需求池提升至此。

## 2. 近期候选（Next，待评审，未承诺）

> 以下为 PM 基于 PRD 风险与场景梳理的**候选**，均处于 New/In Review，需补完需求卡与验收标准、确认降级方案后方可进入 Ready。

| 编号候选 | 标题 | 类型 | 建议优先级 | 价值 / 触发场景 | 主要成本与约束 |
| --- | --- | --- | --- | --- | --- |
| CAND-01 | 多用户与角色（管理员/观看者/访客） | 功能 | W（暂不做，需立项评估） | 多人家庭差异化权限 | 冲击单密码架构，需用户表/会话/RBAC，与零数据库基线冲突，成本高 |
| CAND-02 | 观看记录与片库的定时任务可视化 | 改进 | S | 让兜底扫描、分享清理等后台任务可观测 | 仅管理页聚合，零 schema 变更，成本低 |
| CAND-03 | 新片/续播/评分的站内通知中心 | 功能 | C | 主动提醒未看新片、看到一半的剧 | 需 DB 与通知模型，注意未启用降级 |
| CAND-04 | 播放列表与评分的跨设备同步说明/导入导出增强 | 改进 | S | 已有 JSON 导出，扩展到评分/进度全量备份 | 复用导出框架，需明确文件版本兼容 |
| CAND-05 | 更丰富的智能清单规则（按评分/年份/时长组合） | 改进 | C | 复用 `/smart` 无状态规则引擎 | 规则白名单与 URL 正交需设计 |
| CAND-06 | 转码预热/离线预转码 | 功能 | C | 提前转好常用片，减少等待 | 高磁盘/CPU，必须有开关与配额，低配慎用 |

## 3. 远期方向（Later，方向性备忘）

- **多用户/RBAC**：仅当家庭多人差异化权限成为高频刚需时启动，需同步评估持久化与部署形态变更（见 CAND-01）。
- **客户端/开放 API 成熟化**：在现有 JSON API 稳定后，评估鉴权令牌（Token）与 API 版本化，供第三方客户端接入。
- **更广义的媒体库**：音乐/照片等非视频媒体的纳入评估（当前聚焦视频，避免范围蔓延）。
- **可观测性增强**：Prometheus 指标端点等运维向能力，按实际部署反馈决定。

## 4. 已交付能力基线（历史归档）

> 以下能力均已发布并受测试覆盖，作为 PRD 第 5 节的实现基线；后续变更走新需求，不原地修改历史结论。

### 4.1 媒体库与播放核心
- 递归扫描、fsnotify 增量监听（防抖/晚挂载重试）、定时全量兜底、手动 rescan 与孤儿清理。
- HTTP Range 流式播放、下载、倍速、键盘快捷键、字幕字号。
- ffmpeg 缩略图按需生成与缓存，缺 ffmpeg 占位图降级。
- 剧集自动分组（SxxEyy/1xx/中文/EP）、首页折叠、剧集详情、自动连播。

### 4.2 转码与字幕
- HLS 按需转码、原画 + 1080p/720p/480p、自适应 ABR、并发排队与空闲回收、VAAPI 硬解回退。
- 多音轨探测与切换；外挂字幕统一转 WebVTT、内嵌文本字幕提取、位图字幕可选 OCR。
- 转码任务管理页（会话查看/终止）。

### 4.3 元信息与组织
- 本地 NFO/海报背景识别与自动刷新；TMDB 单视频人工刮削与全库批量刮削（单任务/节流/进度）；手动元信息编辑。
- 影片详情页与四级相似推荐；演员/导演人物聚合；目录浏览、搜索、智能清单。
- 新片时间线与"新"角标（ModTime，零额外存储）；随机看看。

### 4.4 个性化与持久化（需 DB）
- 播放进度/续播提醒/观影历史（含 CSV 导出）、收藏、稍后再看、1–5 星评分与我的高分、视频标签与批量操作。
- 播放列表/合集（整剧加入、手动排序、列表连播、JSON 备份导入导出）。
- 片头片尾跳过、视频书签/时间戳笔记。

### 4.5 分享、安全与运维
- 匿名文件分享（有效期白名单、口令哈希、失败限流、过期懒清理与定时清理、管理中心）。
- 可选访问密码（HMAC Cookie、登录限流、开放重定向防护）；路径穿越白名单等安全基线。
- `/healthz`、数据健康（SQLite 孤儿）、缓存健康（缩略图/TMDB 孤儿）、片库存储分析、优雅关闭/日志/panic 恢复、PWA Service Worker。

## 5. 需求池维护规则

1. 任何口头/对话需求先登记为候选（New），补全 [需求卡模板](./01-需求管理流程与PM把关规范.md#7-需求卡标准模板) 后进入评审。
2. 需求池文件可随规模增长拆分为 `requirements/REQ-*.md`，本文件只保留索引与阶段归属。
3. 每轮规划结束更新状态与归属（Now/Next/Later），并在需求卡留痕变更原因。
4. W（本期不做）不等于永久否决，须写明搁置原因，达到触发条件时重新评审。
5. 所有进入 Ready 的需求必须通过 DoR 清单，并明确可选能力的降级形态。
