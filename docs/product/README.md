本目录是 vedio-website 的产品经理工作区。**所有需求都必须先经过产品经理角色把关**，按下面的制度与模板流转，再进入开发。

## 需求流转速记

```
新建 New → 评审中 In Review → 已就绪 Ready → 开发中 In Dev → 待验收 In QA → 已发布 Released
                                  └ 不满足 DoR 打回；验收不通过 Reopened
```

1. 提需求：在 [需求池](./03-路线图与需求池.md) 登记候选（New），复制需求卡模板到 `requirements/`。
2. PM 把关：按 [DoR 清单](./01-需求管理流程与PM把关规范.md#4-需求把关清单definition-of-ready) 澄清价值、范围、降级与验收标准，定 MoSCoW 优先级。
3. 开发：满足 DoR 才进入 In Dev；变更走变更控制，禁止顺手加功能。
4. 验收：按可测验收标准逐条验收，满足 [DoD](./02-产品需求文档PRD.md#8-全局验收基线definition-of-done)（build/vet/test 全绿、模板实渲染、SW 缓存版本同步、降级双路径）后发布。

## 不可突破的产品基线（一票否决）

- 零数据库默认可运行；持久化能力未启用时 API 503、UI 友好降级。
- 单二进制 + go:embed，不引入运行期外部前端构建链。
- 高资源任务（转码/OCR/批量）必须有开关、上限与降级，默认面向低配 NAS。
- 安全基线：路径穿越防护、签名 Cookie、口令哈希、失败限流。
- 中文交付；提交信息不使用"第 N 轮/期"等无业务含义字样。
